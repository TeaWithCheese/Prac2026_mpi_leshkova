### Обоснование выбора алгоритма для параллельной реализации

Для того, чтобы реализовать построение полудискретной системы, описанной в задаче, необходимо реализовать операторы `M` (диагональная матрица теплоемкостей), `K` (матрица пространственных операторов) и вектор правой части `f(t)` (источники тепла и граничные условия). Все три части системы имеют хороший потенциал для параллелизации: задача предполагает большое число ячеек (`N_z`, что также является размерностью каждого из трёх векторов), при этом для каждого из трёх векторов вычисление отдельно взятого индекса происходит независимо от остальных (необходимость в коммуникации между рангами в процессе вычисления отсутствует). Учитывая объем арифмитических оператий, вычисление диапазонов вектора на различных рангах поможет добиться достаточного ускорения алгоритма.

### Результаты запусков на суперкомпьютере

Исследование сильной масштабируемости проводилось на суперкомпьютере «Ломоносов-2» (раздел compute). Размер задачи фиксировался, количество процессов варьировалось от 1 до 16. Программно-аппаратная среда: язык Julia 1.11.5, библиотека MPI.jl (поверх системного OpenMPI 4.0.0-icc), компиляция с опциями по умолчанию (уровень оптимизации -O2).

### График сильной масштабируемости
$\quad$

<img src="thermal-diagnostics/pics_for_report/scaling_plot.png" alt="scaling plot" width="558">

- Эффективность параллельной реализации ограничена затратами на передачу данных при сборе результатов и репликации вектора (MPI_Gatherv)
- На 4 процессах наблюдается сверхлинейное ускорение, что объясняется переходом от вычислений на одном ядре к использованию совокупной пропускной способности кэш-памяти и оперативной памяти нескольких узлов
- Снижение эффективности при переходе от 8 к 16 процессам связано с уменьшением размера локального блока данных на каждом ранге, из-за чего накладные расходы на пересылку данных начинают расти быстрее, чем объем полезных вычислений. Если увеличить число ячеек в сетке, то доля накладных расходов уменьшится
